# 轻舟 LiteArk 网盘功能说明

> 本文描述网盘侧（文件存储、上传下载、预览、共享）的功能与实现细节，内容与当前代码一致。
> 文件夹权限模型、授权配置见《[权限说明](权限说明.md)》。

## 一、概述与入口

轻舟是一套可完全内网离线部署的私有网盘，前后端打成单一 fat jar，内网服务器只需 JDK 1.8。

| 入口 | 路径 | 鉴权 |
|------|------|------|
| 前台网盘 | `/`、`/files`、`/recent`、`/shares`、`/recycle`、`/profile` | 需登录（JWT） |
| 管理后台 | `/admin/overview` 等 | 需 `role_id = 1` |
| 免登录共享页 | `/s/{token}` | 按共享权限与访问密码校验 |

技术栈：SpringBoot 2.7.18 + Java 8 + MyBatis-Plus + SQLite；前端 Vue3 + Element Plus。

**账号相关**：登录、注册（账号 3–32 位，密码至少 6 位）、修改密码（校验原密码）、修改昵称、配额环形图展示。JWT 有效期 7 天；修改密码后需重新登录。

## 二、页面与导航

| 页面 | 内容 |
|------|------|
| 全部文件 `/files` | 左侧目录树（含「共享给我的」入口）、面包屑、工具栏、文件区、多选操作栏；支持 URL 直达 `?folder=<id>` |
| 最近 `/recent` | 根目录（含共享入口）前 50 条，按文件夹优先、修改时间倒序；点击文件夹进入，点击文件预览 |
| 我的分享 `/shares` | 共享链接列表（复制/访问记录/撤销）+「文件夹授权」区块（查看/撤销/打开文件夹） |
| 回收站 `/recycle` | 已删除项列表、还原、彻底删除、清空 |
| 我的 `/profile` | 昵称、密码、配额 |

**三端响应式**

- 桌面（≥1200px）：左侧固定目录树 + 主内容区 + 顶部用户栏
- 平板（768–1199px）：抽屉菜单
- 移动（<768px）：单列内容 + 底部四 Tab（文件/最近/共享/我的）+ 右下悬浮上传按钮 + 默认网格视图 + 多选模式
- 断点覆盖 320–1920px，触屏热区 44px

## 三、目录与文件管理

| 操作 | 说明 | 需要的权限 |
|------|------|-----------|
| 浏览目录 | 目录树、面包屑、列表/网格视图；列表每行带自身权限 | `view` |
| 搜索 | 按名称关键词在当前目录内过滤（后端 `like`） | `view` |
| 新建文件夹 | 根目录或任意目录内创建 | 父目录 `upload` |
| 重命名 | 文件与文件夹均可 | 所在目录 `edit` |
| 复制 | 多选、跨目录、文件夹递归复制；同名按策略处理 | 目标 `upload` + 源 `view` |
| 剪切/粘贴 | 多选、跨目录移动 | 目标 `upload` + 源 `edit` |
| 删除 | 移入回收站（不物理删除） | `edit` |
| 还原/彻底删除/清空回收站 | 仅所有者本人可操作 | 所有权 |

**排序**：后端固定「文件夹优先，同级按修改时间倒序」，前端不提供列排序。

**同名处理**（`liteark.conflict-strategy` / 系统配置 `conflict_strategy`）：

| 策略 | 行为 |
|------|------|
| `rename`（默认） | 自动追加序号：`报告.pdf` → `报告(1).pdf` → `报告(2).pdf` |
| `skip` | 跳过，不覆盖，返回「已跳过（同名）」 |
| `overwrite` | 覆盖同名文件（先删旧实体与记录再写入） |

## 四、上传

### 4.1 界面入口

| 端 | 入口 |
|----|------|
| 桌面 | 「上传文件」（多选任意类型）、「上传文件夹」（整目录）、文件区拖拽（文件与文件夹均可，文件夹递归展开后平铺到当前目录，拖入时显示虚线高亮） |
| 移动 | 右下 FAB → 底部面板：「从相册选择 / 选择文件」+「拍照上传」；不支持文件夹批量上传与拖拽 |

无 `upload` 权限时，上传/新建入口直接隐藏，接口也会返回 403。

### 4.2 分片断点续传

界面所有上传**统一走分片通道**（`/api/upload/*`），小文件同样分片，逻辑只有一条路径。

```
前端                                        服务端
 │ 1. 分片读取计算全量 MD5（每次 4MB）        │
 │ 2. POST /api/upload/init ─────────────────▶│ 校验目录 upload 权限、单文件上限、配额
 │                                           │ 命中未过期的同 md5+同名+同目录任务 → 返回已传分片
 │◀──────────────── uploadId + uploaded[]     │ 否则新建任务（7 天过期）
 │ 3. POST /api/upload/chunk（并发 N 个）─────▶│ 校验分片尺寸，落盘 chunks/{uploadId}/{index}.part
 │                                           │ 已存在且尺寸一致则跳过写入（幂等）
 │ 4. POST /api/upload/complete ─────────────▶│ 校验分片齐全 → 合并 → 校验合并后 MD5 → 落库 + 更新配额
 │◀──────────────── 文件记录                   │
```

约束与默认值：

| 项 | 值 |
|----|-----|
| 分片大小 | 1MB–64MB，默认 PC 8MB、移动 2MB（系统配置 `chunk_size_pc` / `chunk_size_mobile`） |
| 单文件分片并发 | 默认 PC 4、移动 2（`upload_concurrency_pc` / `upload_concurrency_mobile`） |
| 多文件并发 | 一次选择/拖入多个文件时最多 **3 个文件同时上传**（`MAX_PARALLEL_UPLOADS`），其余排队等待；单次请求并发上限 = 3 × 单文件分片并发 |
| 单文件上限 | 默认 2GB（`max_file_size`，同时受 `liteark.max-file-size` 约束） |
| 任务有效期 | 7 天，过期任务连同分片被清理 |
| 分片校验 | 服务端按 `min(chunkSize, totalSize - index*chunkSize)` 校验每片字节数，不符即报错 |
| 合并校验 | 合并后重新计算 MD5，与 init 声明值不一致则拒绝落库并清理 |

> 说明：这里的 MD5 用于**同一文件的断点复用**（重新选择同一文件时沿用任务与已完成分片），**不是跨文件秒传**——相同内容的不同文件仍各自存储一份。

### 4.3 上传队列与断点恢复

- 一次选择/拖入的多个文件**并行上传**：最多 3 个文件同时在传（每文件内部再按分片并发），队列里其余文件显示「排队中」，任一文件完成即自动补位。
- 队列展示实时进度、状态文案、暂停/继续/取消；排队中的任务也能暂停（让出并发位，不占名额）或取消。
- 单文件失败不影响同批其他文件；批量上传结束只汇总一条提示（成功/失败/取消条数），单文件上传仍逐条提示。
- 单分片超时 30s，失败自动重试 3 次（退避 0.5s/1s/1.5s），仍失败则任务置为失败。
- 进度写入 `localStorage`（键 `liteark_uploads_v1`，保留最近 30 条），刷新或断网后重新打开页面会提示「发现 N 个未完成上传」。
- 浏览器不允许脚本读取本地文件，恢复时需**重新选择相同文件**（按 MD5 + 名称 + 大小匹配），服务端已完成分片不重传。
- 取消任务会同时调用服务端 `/api/upload/cancel` 清理分片。
- 并行完成后列表、目录树、配额刷新做了 300ms 合并，避免多文件同时完成时反复请求。

### 4.4 兼容接口

`POST /api/files/upload`（`multipart`，字段名 `files`，参数 `parentId`）保留为普通一次性上传接口，供脚本或第三方集成使用；界面不再调用。

### 4.5 配额与归属

- 配额按**文件所属用户**计算：写入他人授权目录时，文件归属该目录所有者，占用其配额。
- 上传前校验目标所有者 `used + size ≤ quota`，超限返回「空间配额不足」。
- 回收口径：**移入回收站不减**（文件实体还在），**彻底删除 / 清空回收站 / 定时过期清理时按实际字节数退回**。历史版本（`doc_version`）不单独计配额。
- 新用户默认配额 20GB（`liteark.default-quota` / `default_quota`）。

### 4.6 校验值计算（上传前的第一个阶段）

- 全量 MD5 按 4MB 分片读，`spark-md5` 增量累加，大文件不会一次性载入内存。
- 队列里显示「计算文件校验值 xx%」，进度随每片读取推进；此阶段不发任何网络请求。
- 单次读取有 120 秒看门狗：文件放在 iCloud / OneDrive 等云盘尚未下载到本地时，`FileReader` 可能既不触发 `load` 也不触发 `error`，此时给出「读取文件超时，请确认文件已下载到本机后再上传」而不是无声卡住。
- 读取失败、被中断、`spark.append` 抛异常都会显式失败并显示原因，不会停在 0%。

## 五、下载

| 方式 | 说明 |
|------|------|
| 单文件 | `GET /api/files/{id}/download`，需 `download` 权限 |
| 批量 ZIP | 多选后打包，`POST /api/files/download-zip`；文件夹递归；无下载权限的项**跳过**而不是整体失败 |
| 共享页下载 | 共享权限为 `download` 或 `edit` 时可用 |

**响应头处理**

- 同时返回 ASCII 兜底名与 RFC 5987 的 `filename*=UTF-8''...`，Chrome/Safari/Edge/Firefox 均按原始中文名保存。
- ZIP 使用 UTF-8 编码并写入 EFS(0x800) 标志位，Windows 资源管理器与 macOS 解压中文名不乱码。
- 支持 HTTP Range（206），大文件可断点续传。

## 六、预览

| 类型 | 扩展名 | 呈现方式 |
|------|--------|---------|
| 图片 | png / jpg / jpeg / gif / webp / bmp / svg | 弹窗内 `<img>`；列表/网格用缩略图（`?w=200/400`），webp、svg 等无法解码时回退原图 |
| PDF | pdf | 浏览器内置阅读器内联（iframe），支持 Range |
| 视频 | mp4 / mov / webm / ogv / m4v | `<video>`，支持拖动进度 |
| 音频 | mp3 / m4a / wav / flac / ogg / aac | `<audio>` |
| Markdown | md | 前端 `marked` 渲染 + `DOMPurify` 净化，支持表格、代码块、引用 |
| CSV | csv | 解析为表格，展示前 200 行，超出提示截断 |
| 其他文本 | txt / json / log / xml / yml 等 | 纯文本按原样展示 |
| Office | docx / xlsx / pptx（旧版 doc/xls/ppt 见下） | 只读预览，双通道 |

**Office 双通道**

1. `xlsx` **固定走 POI 渲染的 HTML**（不论服务器是否装 LibreOffice）：多工作表渲染成 Excel 式**页签**，点哪个看哪个；合并单元格还原为 `colspan/rowspan`，单元格不换行、超长省略并可悬停看全文，列多时横向滚动。原因：LibreOffice 转 PDF 是一张张纸，没有页签，多工作表时用户往往只看到第一个表。
2. `docx / pptx`：服务器装有 LibreOffice（含 headless）→ 转 PDF，保留原版式，缓存于 `temp/`，二次请求命中缓存。
3. 未装 LibreOffice → `OfficeHtmlService` 用 Apache POI 解析并渲染只读 HTML：docx（段落、粗斜体、表格、内嵌图片）、pptx（逐页文本、表格、图片占位）；xlsx 的 HTML 解析失败（如超过 30MB）且装了 LibreOffice 时回退 PDF。
4. 旧版 doc/xls/ppt 且未装 LibreOffice → 返回明确提示「请下载后查看」。

工作表渲染上限：最多 20 个工作表、每个表前 300 行 × 40 列，超出给截断提示；空工作表显示「该工作表为空」，整本没有可显示工作表时给出提示而不是空白页。

前端先调 `GET /api/files/{id}/office-preview/info` 探测能力（`mode = pdf | html | none`，`tabs=true` 表示带工作表页签），再决定内嵌还是提示，避免 iframe 里出现一坨 JSON。

**安全与兼容**

- 内联响应统一 `X-Content-Type-Options: nosniff`。
- HTML/SVG 内联预览附加 `Content-Security-Policy: sandbox`：可渲染但脚本不执行。
- `X-Frame-Options: SAMEORIGIN`（默认 `DENY` 会导致同源 iframe 白屏，PDF/Office 预览不可用）。
- MIME 按扩展名优先判定，规避容器缺少 `/etc/mime.types` 时把 md/csv/webp/mp4 识别为 octet-stream 而触发下载。

## 七、在线编辑与版本

- 支持后缀：默认 `txt,md,csv,json,html`（系统配置 `edit_ext_whitelist`），可在后台调整。
- 总开关：`online_edit_enabled`，关闭后保存接口返回 403。
- **入口与模式**：双击文件一律先进「预览（查看）」，弹窗底部出现「编辑」按钮，点了才切到编辑模式；列表行内也有「编辑」可直接进入。图片、音视频、PDF、Office 没有编辑入口。
- 从预览切编辑直接复用已下载的原文，不重复请求（Markdown 拿到的是原始源码，不是渲染结果）。
- 自动保存：每 30s 检查一次，**仅内容变化时**提交，避免无意义版本。
- 每次保存把旧内容另存为历史版本（`doc_version`），版本号递增。
- 历史版本可查看、可回滚；回滚前先把当前内容存为新版本，再写回目标版本，不会丢当前内容。
- 移动端可编辑与查看版本，回滚入口仅桌面显示。

## 八、回收站

- 删除只做逻辑标记（`is_deleted=1` + `deleted_at`），实体文件保留。
- 回收站列表、还原、彻底删除、清空**仅对所有者本人开放**；被授权者删除的文件进入所有者回收站。
- 还原条件：原目录仍有 `edit` 权限，且原目录不存在同名项（否则提示先重命名）。
- 彻底删除按依赖顺序清理，避免外键约束导致事务回滚：

```
子项优先 → doc_version（含历史版本实体文件）→ share_access_log → share
        → permission（授权规则）→ 文件记录 → 实体文件
```

- 清空回收站额外做兜底：清理「上级已删、下级未同步标记」的残留子项。
- 自动清理：默认保留 30 天（`recycle_retention_days`），定时任务每小时扫描。

## 九、共享链接

| 项 | 说明 |
|----|------|
| 创建 | 需对该文件/文件夹有 `share_external`（外部分享）或 `share_internal`（内部分享）权限；所有者与超级管理员默认拥有全部权限，被授权用户需在权限配置中勾选对应分享位 |
| 分享范围 | 外部分享：任何人凭链接访问（可设密码/有效期/下载上限）；内部分享：仅指定内部用户登录后可访问，无需密码，链接同样为 `/s/{token}` |
| 内部目标 | 内部分享必须至少选择一位站内用户；`share.target_user_ids` 存用户 ID 列表，创建者在名单外也可访问自己创建的分享 |
| 权限 | `view`（可浏览、可预览，不可下载）/ `download`（可下载）/ `edit`（可下载；共享页本身仍为只读，不提供在线编辑，仅作权限标记） |
| 访问密码 | 可选；未带或错误时返回 `NEED_PASSWORD`，页面显示密码输入框 |
| 有效期 | 天数，默认 7 天（`default_share_expire`）；0 表示永久 |
| 下载上限 | 0 表示不限；每次下载计数 +1，达到上限自动置为已撤销（原子更新，并发不超额） |
| 浏览范围 | 共享根及其全部下级；越界访问返回 403（`insideShare` 校验） |
| 访问记录 | 记录时间、IP、UA、端类型（PC/Mobile），列表最多返回 500 条 |
| 共享页 | `/s/{token}` 免登录：文件夹逐级浏览、文件预览/下载、Office 只读预览；移动端同样只读 |

共享链接现在同时覆盖两种场景：外部分享面向**站外匿名访客**，内部分享面向**指定站内用户**（两者都用 `/s/{token}` 链接，内部分享会校验登录身份与名单）；「文件夹授权」仍是把文件夹递归授权给同事的独立机制（见《权限说明》）。

## 十、中文与特殊文件名

- 上传、重命名统一走 NFC 归一 + 非法字符替换（`/ \ : * ? " < > |` → `_`），去除控制字符、首尾空白与结尾的点。
- 名称超过 150 字符自动截断并保留扩展名。
- 重名检测按归一后的名称比较，macOS 的 NFD 组合字符（如 `café`）与 NFC 视为同一文件。
- 空格、括号、`# & % ' +`、emoji、全角标点均可正常存取。
- 路径穿越型文件名（`../../../etc/x.txt`）落库前即被清洗为单段名，实体文件始终存于 `files/{所有者ID}/` 下。

## 十一、自动清理

定时任务（每小时）处理四类数据：

| 对象 | 依据 | 默认值 |
|------|------|--------|
| 回收站 | `recycle_retention_days` | 30 天 |
| 上传分片与过期任务 | 任务 `expire_at` | 7 天 |
| 过期共享 | `expires_at` | 无（按配置） |
| 操作日志 | `log_retention_days` | 180 天 |

## 十二、存储结构

```
data/
├── liteark.db                 # SQLite（含 WAL）
├── files/{所有者ID}/          # 文件实体，按所有者隔离
│   └── {随机key}.{ext}
├── thumbnails/{所有者ID}/{宽}/ # 图片缩略图缓存（jpg）
└── temp/
    ├── chunks/{uploadId}/     # 分片
    ├── office-html/           # POI 渲染的只读 HTML 缓存
    └── office/{md5}/          # LibreOffice 转出的 PDF 缓存
```

备份只需打包 `data/`；迁移拷 jar + conf + data 到新机器即可。

## 十三、接口清单

**文件与目录（`/api/files`，需登录）**

| 方法 | 路径 | 说明 |
|------|------|------|

| GET | `/folder-info?folderId=` | 当前目录 `perms`、`granted`、`ownerName` |
| GET | `/breadcrumb?id=` | 面包屑 |
| POST | `/folder` | 新建文件夹（`parent_id`、`name`） |
| PUT | `/{id}/rename` | 重命名 |
| POST | `/copy` | 复制（`ids[]`、`targetId`） |
| POST | `/move` | 移动（`ids[]`、`targetId`） |
| DELETE | `/?ids=1,2` | 删除到回收站 |
| GET | `/recycle` | 回收站列表（仅本人） |
| POST | `/{id}/restore` | 还原 |

## 十五、边界与排障

**已知边界**

- 无 OnlyOffice 在线编辑，Office 定位为只读预览；POI 通道为「内容可读」级，不还原字体、配色与图片版式，需要原样版式请安装 LibreOffice（`xlsx` 例外：为保证工作表完整可见，固定走页签 HTML，不受 LibreOffice 影响）。
- 电子表格只读：不能改单元格、不能看公式计算过程，图表与图片不渲染（只显示单元格文本与合并结构）。
- 旧版 doc/xls/ppt 无 LibreOffice 时无法在线预览。
- PDF 内联依赖浏览器内置阅读器，iOS Safari 等不支持内联 PDF 的环境需「在新窗口打开」或下载。
- 跨用户复制/移动受限（物理存储按所有者分目录），需先下载再上传。
- 无跨文件秒传（相同内容不同文件各存一份）。
- 「最近」页是根目录前 50 条，不是独立的访问历史。

**排障速查**

| 现象 | 排查顺序 |
|------|---------|
| 上传报 `FileNotFoundException`（相对路径数据目录） | 确认 `data-dir` 已由 `LiteArkProperties#normalizeDirs` 转绝对路径；升级到含该修复的版本 |
| 选文件时只能选文件夹 / 文件灰显 | 「上传文件」与「上传文件夹」是两个独立输入控件，前者不带 `webkitdirectory`；确认前端为当前版本 |
| PDF / Office 预览白屏 | 检查 `X-Frame-Options` 是否为 `SAMEORIGIN`；Office 再用 `/office-preview/info` 看 `mode` 与 `msg` |
| 上传中断后必须重传 | 需重新选择**同一文件**（MD5 + 名称 + 大小匹配）；确认浏览器未清 localStorage |
| 上传卡在「计算文件校验值 0%」 | 先看队列是否有进展（本版本已修：进度会实时刷新）。仍不动则确认文件在本机（云盘占位文件读取会挂起，120 秒后给出超时提示），再看控制台是否有 `FileReader` 报错 |
| 删了文件但空间没释放 | 移入回收站不减配额，需「彻底删除」或「清空回收站」；本版本起三条删除路径（彻底删除 / 清空 / 定时过期）都会退回字节数 |
| 提示配额不足 | 目标目录所有者配额已满（写入他人目录计其配额） |
| 批量下载缺文件 | 缺的项是当前用户无 `download` 权限，设计上跳过而非整体失败 |
| 压缩包中文名乱码 | 确认使用 UTF-8 + EFS 标志（当前实现已处理）；老版本解压工具可能忽略标志位 |
| 共享链接打不开 | 依次检查：是否被撤销、是否过期、下载次数是否达上限、密码是否正确；内部分享还需确认已登录且账号在可访问名单中 |
| 普通用户看不到「分享」按钮 | 该用户对此文件/文件夹没有 `share_internal`/`share_external` 权限，需管理员在角色或文件夹权限中勾选 |
