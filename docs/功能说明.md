## 一、系统构成

| 入口 | 路径 | 说明 |

| 前台网盘 | `/`、`/files`、`/recent`、`/shares`、`/recycle`、`/profile` | 需登录 |

## 二、账号与个人

- 登录、注册（账号 3-32 位，密码至少 6 位）
- 修改密码（校验原密码）、修改昵称
- 个人配额环形图展示（轻量 SVG，无图表库依赖）
- JWT 鉴权，token 有效期 7 天；修改密码后需重新登录
- TOTP 二次验证（可选）：分级开关、验证器绑定/关闭、一次性恢复码、信任设备、管理员重置与审计，详见分册文档

**中文与特殊文件名适配**

- 上传/重命名统一走 NFC 归一 + 非法字符替换（`/ \ : * ? " < > |`），文件名含空格、括号、`# & % ' +`、emoji、全角标点均可正常存取
- 重名检测按归一后的名称比较，macOS 的 NFD 组合字符（如 `café`）与 NFC 视为同一文件
- 名称超长（>150 字符）自动截断并保留扩展名；首尾空白与结尾的点自动去除
- 下载/预览响应头同时返回 ASCII 兜底名与 RFC 5987 的 `filename*=UTF-8''`，Chrome/Safari/Edge/Firefox 均按原始中文名保存
- 批量 ZIP 使用 UTF-8 编码并写入 EFS(0x800) 标志位，Windows 资源管理器与 macOS 解压中文名不乱码
- 路径穿越型文件名（如 `../../../etc/x.txt`）落库前即被清洗为单段名，实体文件始终存于 `files/{用户ID}/` 下

**预览与传输的安全/兼容处理**

- 音视频、PDF 支持 HTTP Range（206），可拖动进度条、断点播放；响应带 `Accept-Ranges: bytes`
- 内联预览统一返回 `X-Content-Type-Options: nosniff`
- HTML/SVG 内联预览附加 `Content-Security-Policy: sandbox`，页面可渲染但脚本不执行，避免同源 XSS 读取登录态
- MIME 按扩展名优先判定，规避部分 Linux 容器缺少 `/etc/mime.types` 时把 md/csv/webp/mp4 识别为 octet-stream 而触发下载
- `X-Frame-Options` 由默认 `DENY` 调整为 `SAMEORIGIN`：PDF / Office 预览是在同源 iframe 内嵌，`DENY` 会让 iframe 直接白屏（表现为"PDF/Office 预览不可用"）；跨站嵌入仍被拒绝

## 四、共享

- 创建共享链接：先选**外部分享**或**内部分享**，再设权限（仅查看/可下载/可编辑）、有效期（天）、下载次数上限（0 不限，达上限自动失效）；外部分享可另设访问密码
- 内部分享：选择一位或多位站内用户，仅这些用户登录后可访问（文件与文件夹均支持），无需密码；我的分享中显示类型与分享对象
- 能否分享由权限位 `share_internal` / `share_external` 控制，在角色权限或文件夹权限配置中勾选；所有者与超级管理员默认可用
- 我的分享：列表、复制链接、查看访问记录、撤销
- 免登录访问页：文件夹共享支持逐级浏览，文件共享支持预览/下载（按权限）
- 访问记录：记录时间、IP、UA、端类型（PC/Mobile）
- 后台共享管控：修改权限/密码/有效期、撤销

## 八、需求全量对齐与剩余边界

V1.1 核心版曾列出 10 项未实现能力，现已补齐 9 项：

1. **分片断点续传**：MD5 全量校验、分片落盘/合并校验、断点复用、进度本地持久化、暂停/继续/取消、弱网重试、按端分片与并发配置
2. **Office 只读预览**：双通道 —— 服务器装有 LibreOffice 时 headless 转 PDF（高保真，保留版式）；没有 LibreOffice 时用 Apache POI 解析 docx/xlsx/pptx 渲染只读 HTML（文字、表格、分页可看，不需要外部程序）；移动端与共享页一律只读
3. **细粒度 RBAC**：文件夹级四权限位（查看/编辑/下载/上传）、授权他人已有文件夹后自动出现在其网盘、递归继承与上级约束、用户规则优先于角色规则、阻断继承、权限查询、文件操作接口实时校验、后台配置页
4. **文档版本回滚**：回滚前自动备份当前版本，生成新版本号
5. **回收站自动清理**：默认 30 天，定时任务每小时扫描；同时清理过期分片、过期共享与超期日志
6. **移动端编辑**：TXT/MD 纯文本编辑 + 30s 自动保存；历史版本只读，回滚入口仅在 PC 显示
7. **共享下载限制**：可配置下载次数上限，达上限自动失效并给出明确提示
8. **日志导出**：按当前筛选条件导出 UTF-8 BOM CSV
9. **后台 IP 白名单 + 接口文档**：白名单拦截已生效；springdoc 已打包但默认关闭

剩余边界：

- **OnlyOffice 在线编辑**：需求 §10 Q-11 标记为待定方案，本期不引入第三方编辑服务；Office 能力定位为只读预览
- **LibreOffice 运行时**：非必需。装有 LibreOffice 时 Office 预览为 PDF 高保真；未装时 docx/xlsx/pptx 自动走 POI 只读 HTML（版式简化：不还原字体/配色/图片排版），旧版 doc/xls/ppt 仍建议装 LibreOffice
- **文本存储备选模式**：本期定版 SQLite，未实现 JSON/YAML 存储切换
- **双架构验证记录**：amd64/arm64 运行验证需在目标信创机器实测
- **共享默认有效期**：后台配置项暂未联动前端表单（表单默认 7 天）
- **PDF 内联预览**：依赖浏览器内置 PDF 阅读器；iOS Safari 等不支持内联 PDF 的环境，用预览弹窗的「在新窗口打开」或下载查看

### PDF / Office 预览不可用专项修复（2026-11-24 复验）

- 现象：docx、pdf、xlsx 点「预览」全部白屏，图片/音视频正常
- 根因：Spring Security 默认下发 `X-Frame-Options: DENY`，而这三类都是同源 `iframe` 内嵌（图片走 `<img>`、音视频走 `<video>`，不受该头限制）；Office 另叠加"服务器未装 LibreOffice → 503 JSON"，iframe 里只剩一坨 JSON
- 修复：
  1. `SecurityConfig` 将 `X-Frame-Options` 改为 `SAMEORIGIN`，同源内嵌放行、跨站仍拒绝；PDF 立即恢复浏览器内置阅读器渲染
  2. Office 预览改为双通道：装有 LibreOffice → 转 PDF；未装 → `OfficeHtmlService` 用 Apache POI 解析 docx（段落/粗斜体/表格/内嵌图片）、xlsx（多工作表、前 300 行 × 40 列、`DataFormatter` 取值）、pptx（逐页文本、表格、图片占位）渲染成只读 HTML，缓存于 `temp/office-html/<md5>.html`
  3. 新增 `GET /api/files/{id}/office-preview/info` 能力探测，前端据 `mode=pdf|html|none` 决定内嵌还是显示"请下载查看"，不再把 JSON 塞进 iframe
  4. 共享页 `office-preview` 同步走同一双通道
- 复验：真实 docx（中文段落 + 3×3 表格）、xlsx（两工作表 + 数字）、pptx（3 页含表格）在 Chrome 中 iframe 内正常渲染，中文无乱码；PDF 显示内置阅读器工具栏与页面内容；接口回归 117 项全通过；服务端 0 ERROR
- 说明：POI 通道为"内容可读"级预览，不还原字体、配色与图片版式；需要原样版式时在服务器安装 LibreOffice，接口会自动优先走 PDF

### 上传入口专项修复（2026-11-24 复验）

- 现象：桌面端点「上传」后弹出的是"选择文件夹"对话框，文件列表里的 pptx / docx / pdf 等文件呈灰显、无法勾选，看起来像"很多格式传不了"
- 根因：桌面「上传」按钮绑定的 `<input type="file">` 带了 `webkitdirectory` 属性，浏览器只会打开目录选择器；目录选择器里文件本身不可选（macOS 下文件行灰显），只有文件夹能选
- 修复：拆成两个输入控件 —— `#native-file`（`multiple`，无 `webkitdirectory`）用于「上传文件」，`#native-folder`（`webkitdirectory`）用于新增的「上传文件夹」按钮；同时补上文件区拖拽上传（`dataTransfer.items` + `webkitGetAsEntry` 递归展开文件夹），拖入时显示虚线高亮提示
- 复验：Chrome 中 `#native-file` 已无 `webkitdirectory` 且带 `multiple`；一次选择 docx / pdf / pptx 三个文件，全部进入上传队列并完成，列表尺寸与本地一致；服务端无异常

### 文件夹细化权限（2026-11-24 新增）

**能力**

- 管理后台「文件夹权限」可按**普通用户**或**角色**，对系统内**已有文件夹**（含他人空间中的文件夹）配置六项权限：
  - 文件查看：列表可见、在线预览（图片/音视频/PDF/Office/文本）
  - 文件编辑：在线编辑保存、重命名、删除到回收站、历史版本回滚
  - 文件下载：下载原文件、批量打包下载、压缩包内包含
  - 文件上传：上传文件、新建子文件夹、粘贴复制/剪切内容
- 授权后，被授权用户在网盘根目录与左侧目录树中直接看到该文件夹（目录树只显示文件夹名，不显示所有者），列表标注「共享」，进入后顶部显示共享横幅与自身权限标签，按钮按权限自动收放（无上传权限不显示上传/新建，无编辑权限不显示重命名/删除）。

**递归与继承规则**

1. 规则挂在文件夹上，**实时按目录链计算**，因此对该文件夹的全部下级生效，且**后续新增的文件与文件夹自动沿用**，不需要二次配置。
2. **上级权限默认包含下级**：沿目录链自上而下逐层取交集，下级只能在上级授权范围内收窄，不会因配置子目录而放大权限。例如父目录给「查看+下载」，子目录配「查看」，则子目录内只能查看不能下载。
3. **阻断继承**（关闭“继承上级权限”）：该层规则成为新的权限边界，不再向上取上级规则，适合「某个子目录单独授权」的场景。
4. **角色是文件夹权限的默认载体**：给角色配置的目录规则即该角色的默认文件夹权限，角色下所有用户（含后续新增用户）自动继承；同一文件夹上同时存在用户规则与角色规则时，**用户规则优先**（按角色授权的用户规则会用角色默认权限实时取值，见下节）。`delete`/`share` 等旧版权限位自动归并为「编辑/查看」，历史规则继续可用。
5. 根目录不参与配置：授权必须落在具体文件夹上，根目录下的文件只有所有者可见。

**默认权限**

- 超级管理员：全部权限。
- 资源所有者：该文件夹链上没有针对自己的规则时默认全权；一旦管理员为其配置了规则（例如仅「查看」），则按规则生效，可用于限制本人目录的下载/上传。
- 其他用户：未被授权即**完全不可见**（列表不出现、接口返回 403），不再有“未配置即全放”的旧行为。

**数据归属**

- 被授权者在他人文件夹内上传的文件、新建的文件夹，**归属该文件夹的所有者**，配额也计入所有者；所有者可立即看到，不会出现“同一目录两种所有者”的脏数据。
- 被授权者删除文件进入的是**所有者的回收站**。
- 跨用户复制/移动受限（物理存储按所有者分目录），提示先下载再上传；跨用户分享仍只允许所有者创建。

### 普通用户自助授权（2026-11-24 新增）

此前只有管理员能在后台配置文件夹权限，普通用户要共享文件夹只能走「公开链接」。本期补上**用户侧入口**：文件夹所有者可以自己把文件夹授权给同事，无需管理员介入。

**入口**

1. 进入自己拥有的文件夹 → 工具栏「授权」按钮。
2. 列表行内操作 → 文件夹行「授权」（仅自己的文件夹显示）。
3. 移动端单项操作面板 → 「授权给同事」。
4. 已授权内容集中在「我的分享」页「文件夹授权」区块，可查看路径/对象/权限/继承状态，支持**撤销**与「打开文件夹」跳转（URL 带 `?folder=<id>` 可直接定位）。

**面板能力**

- 选择同事（下拉可搜索，已授权者带“已授权”标记，选中后回填其现有权限，避免误以为会追加）。
- 「授权方式」可选**直接指定权限**或**按角色授权**（后者读取角色在本目录的默认权限，勾选项作为上限，界面显示实际生效权限）。
- 六项权限勾选（含内部分享/外部分享）+ 快捷预设（只读 / 可上传 / 全部）；权限说明实时提示。
- 「继承上级权限」开关：关闭即在该文件夹形成新的权限边界。
- 已授权列表（含下级目录上的规则）：本层规则可直接撤销，下级目录的规则标注「下级」并提示去对应目录处理。

**约束（与管理员配置的差异）**

- **只能对自己拥有的文件夹授权**，不能碰他人目录；管理员不受此限（仍用后台配置页）。
- **可授出的权限不超过自己在目标文件夹上的有效权限**（管理员若对所有者本人做了收窄，用户也无法借此放大）。
- 授权对象仅限普通用户：不能给自己授权，也不能给管理员授权（管理员本身已全权）。
- 权限模型与管理端完全一致：挂在文件夹上、递归覆盖全部下级、后续新增自动沿用、上级约束下级、空权限等于“不可见”。

**顺带修复**

- **彻底删除/清空回收站 500**：带历史版本的文件或含子项的文件夹执行「彻底删除」时，因 `doc_version`、`share` 外键约束导致事务回滚并报 500。现按“子项优先 + 先清历史版本（含实体文件）/共享访问记录/授权规则，再删记录”的顺序清理；清空回收站同时清理“上级已删、下级未同步标记”的残留子项。文件夹彻底删除时其上的授权规则一并清除，不再留下指向已删目录的孤儿规则。

### 角色默认文件夹权限与「按角色授权」（2026-11-24 新增）

**调整原因**：此前文件夹权限只能逐个用户配置，人员一多就要重复配 N 遍，且角色调整后用户不会跟随。现改为「**角色持有默认文件夹权限，用户按需继承或引用**」——配置一次、按岗位复用、新增/调岗人员自动生效。

**角色侧（角色管理 → 修改权限）**

- 每个角色一个「修改权限」抽屉：默认只显示文件夹权限列表与「新增规则」按钮；点列表行内「编辑」或「新增规则」后，下方才展开权限操作区（所有者/文件夹/六项权限/继承开关），点底部「保存修改」或「保存权限」生效，点「取消/收起」收起。规则递归覆盖全部下级。
- 角色下所有用户自动获得该权限（新用户加入角色即生效）；角色默认权限调整后，继承者同步生效。
- 超级管理员角色不可配置（本身全权）。删除角色时自动清理其默认规则，并把引用它的用户规则降级为「直接指定」，保留原上限，不会因删角色而丢权限或放大。

**用户侧（文件夹权限页 / 网盘授权弹窗）**

- 授权对象默认「角色」；需要单独调整某个用户时再切「具体用户」。
- 用户授权支持两种来源：
  - **直接指定**：权限固定为勾选值，不随角色变化；
  - **按角色授权**：选一个角色模板，规则记录来源角色（`source_role_id`），**实际权限 = 角色在该目录的默认权限 ∩ 本次勾选的上限**。角色默认配置调整后该用户自动跟随，同时永远不会超过当初设定的上限（例如「给他这个角色的权限，但不允许下载」）。
- 勾选框在按角色模式下表示**上限**，界面实时显示「实际生效」权限，避免误判。
- 规则表与「我的分享」展示来源：`角色 · 名称` 或 `直接指定`；角色规则在用户侧只读、标注「角色默认」，统一由管理员在角色管理中维护。
- 「可授出范围」约束不变：按角色授权同样不超过授权人在目标文件夹上的有效权限。

**接口**

- `GET /api/admin/permissions/role-effective?roleId=&folderId=`：角色在某目录的默认权限 + 角色下用户数（面板回填与预览）。
- `POST /api/admin/permissions` 新增可选 `sourceRoleId`（仅用户规则有效；1 号管理员角色不可作为模板）。
- `POST /api/grants` 新增可选 `roleId`；`GET /api/grants?folderId=` 新增 `roles`（可选角色模板及其在本目录的默认权限）与候选用户的 `roleId / roleName / sourceRoleId`；`GET /api/grants/mine` 新增 `sourceRoleId / sourceRoleName / cap`。
