# 轻舟 LiteArk V1.1 配置说明

## 一、配置层次与优先级

优先级从高到低：

1. **命令行参数**：`java -jar liteark.jar --server.port=9090 --liteark.jwt-secret=xxx`
2. **外置配置文件**：`--spring.config.location=/opt/liteark/conf/application.yml`
3. **jar 内置配置**：`src/main/resources/application.yml`

内网部署推荐方式：jar + 外置 `conf/application.yml`，jar 内配置作为默认值兜底。

## 二、后端内置配置（application.yml）

| 配置项 | 默认值 | 环境变量 | 说明 |
|--------|--------|----------|------|
| `server.port` | 8080 | LITEARK_PORT | HTTP 端口 |
| `spring.datasource.url` | jdbc:sqlite:${liteark.data-dir}/liteark.db | — | 数据源，跟随 data-dir |
| `spring.datasource.hikari.maximum-pool-size` | 1 | — | SQLite 单写，连接池固定 1 |
| `spring.servlet.multipart.max-file-size` | 2048MB | LITEARK_MAX_FILE | 单文件上传上限 |
| `spring.servlet.multipart.max-request-size` | 4096MB | LITEARK_MAX_REQUEST | 请求体上限 |
| `liteark.data-dir` | ./data | LITEARK_DATA_DIR | 数据根目录 |
| `liteark.files-dir` | {data-dir}/files | LITEARK_FILES_DIR | 文件实体目录 |
| `liteark.temp-dir` | {data-dir}/temp | LITEARK_TEMP_DIR | 临时目录 |
| `liteark.jwt-secret` | 开发默认值 | LITEARK_JWT_SECRET | JWT 签名密钥，生产必改 |
| `liteark.totp-master-key` | 空（由 jwt-secret 派生） | LITEARK_TOTP_MASTER_KEY | 二次验证密钥加密与恢复码哈希主密钥，建议独立配置 |
| `liteark.jwt-expire-ms` | 604800000 | — | token 有效期（7 天） |
| `liteark.max-file-size` | 2147483648 | LITEARK_MAX_FILE_BYTES | 业务层单文件上限（2GB） |
| `liteark.default-quota` | 21474836480 | — | 新用户默认配额（20GB） |
| `liteark.conflict-strategy` | rename | — | 同名冲突策略 |
| `liteark.admin-ip-whitelist-enabled` | false | — | 后台白名单开关，已生效（拦截 /admin/** 与 /api/admin/**） |
| `liteark.admin-ip-whitelist` | 127.0.0.1,::1 | — | 白名单，支持精确 IP、`10.10.` 前缀与 `*` |

| `logging.file.name` | ./logs/liteark.log | LITEARK_LOG_FILE | 日志文件 |

**目录创建机制**：应用启动前由 `DataDirPostProcessor` 读取最终配置（含命令行与外置覆盖），自动创建 data-dir / files-dir / temp-dir。因此数据源 URL 只需引用 `liteark.data-dir`，无需担心目录不存在。

## 三、后台系统配置（system_config 表）

这些配置存在数据库中，通过管理后台「系统配置」页修改，即时生效（除非特别说明）：

| 配置键 | 默认值 | 用途 | 生效情况 |
|--------|--------|------|----------|
| `chunk_size_pc` | 8388608 | PC 分片大小（8MB） | 分片初始化时下发给前端并服务端校验 |
| `chunk_size_mobile` | 2097152 | 移动端分片大小（2MB） | 同上 |
| `upload_concurrency_pc` | 4 | PC 上传并发 | `/api/upload/config` 下发 |
| `upload_concurrency_mobile` | 2 | 移动端上传并发 | `/api/upload/config` 下发 |
| `max_file_size` | 2147483648 | 单文件上限 | 普通上传与分片上传均实时校验；multipart 上限另见内置配置 |
| `conflict_strategy` | rename | 同名冲突策略 | 两类上传均读取，rename/skip/overwrite 三选一 |
| `recycle_retention_days` | 30 | 回收站保留天数 | 定时任务每小时扫描一次，到期物理清理 |
| `log_retention_days` | 180 | 操作日志保留天数 | 同上定时任务清理 |
| `office_preview_enabled` | true | Office 转码预览开关 | 关闭后接口返回明确提示，前端降级为下载查看 |
| `online_edit_enabled` | true | 在线编辑总开关 | 关闭后保存接口拒绝 |
| `edit_ext_whitelist` | txt,md,csv,json,html | 可编辑后缀白名单 | 服务端二次校验 |
| `default_share_expire` | 7 | 共享默认有效期 | 前端表单默认 7 天，暂未联动读取 |
| `site_name` | 轻舟 LiteArk | 站点名称 | 展示 |
| `default_quota` | 21474836480 | 默认配额展示 | 新建用户实际取后端 `liteark.default-quota` |
| `totp_global_enabled` | false | 二次验证总开关 | 关闭后不能新增绑定；已绑定账号登录仍按验证码校验 |
| `totp_max_attempts` | 5 | 验证码连续错误阈值 | 达到阈值后临时锁定，恢复码仍可登录 |
| `totp_lock_minutes` | 30 | 锁定时长（分钟） | 到期自动解锁 |
| `totp_window` | 1 | 时间容错窗口 | 前后各 N 个 30 秒步长 |
| `totp_recovery_count` | 10 | 每次生成的恢复码数量 | 重新生成时旧批次全部作废 |
| `totp_disable_policy` | A | 管理员禁用后的处置策略 | A=保留绑定；B=清除密钥并解除绑定 |
| `trusted_device_ttl_days` | 30 | 信任设备有效时长（天） | 到期自动清理并写审计 |

## 五、前端配置

前端工程在 `web/`，构建产物拷入 `src/main/resources/static/` 后随 jar 交付。

- `web/vite.config.js`：开发端口 5173，`/api` 代理到后端 8080
- `web/src/api/index.js`：API 基础路径 `/api`，超时 120 秒；自动附带 Authorization 头与 X-Client-Type（PC/Mobile）
- 响应式断点由 `web/src/styles/main.css` 控制（320–1920px，触屏热区 44px）
- `web/src/utils/uploader.js`：SparkMD5 全量校验、分片队列、暂停/继续/取消、localStorage 进度持久化
- Markdown 预览使用 `marked` + `DOMPurify`（已做 XSS 过滤），CSV 仅渲染前 200 行

前端开发命令：`cd web && npm install && npm run dev`。

## 七、存储路径与备份迁移

```
{data-dir}/
├── liteark.db           # 数据库主文件
├── liteark.db-wal/-shm  # WAL 日志（运行时生成）
├── files/{用户ID}/      # 文件实体
├── thumbnails/{用户ID}/{宽度}/  # 图片缩略图（200/400px）
└── temp/
    ├── chunks/{uploadId}/       # 分片临时文件（合并/取消/过期后清理）
    └── office/{缓存键}/         # LibreOffice 转码后的 PDF 缓存
```

备份（服务停止后执行，避免 WAL 未落盘）：
```bash
tar -czf liteark-backup.tar.gz /opt/liteark/data /opt/liteark/conf
```

迁移：拷贝 `liteark.jar` + `conf/` + `data/` 到新机器，按同样路径放置后启动即可。

## 八、安全配置建议

1. **修改 JWT 密钥**：外置配置中 `liteark.jwt-secret` 设为长随机字符串（如 `openssl rand -hex 32` 的输出）
2. **独立设置二次验证主密钥**：`liteark.totp-master-key` 单独生成，不要与 JWT 密钥相同；修改后已绑定用户需由管理员重置
3. **修改初始密码**：admin/admin123 与 demo/123456 必须更换
4. **后台访问控制**：在 Nginx 层限制 `/admin`：
   ```nginx
   location /admin {
       allow 192.168.1.0/24;
       deny all;
       proxy_pass http://127.0.0.1:8080;
   }
   ```
5. **HTTPS**：启用二次验证时必须由 Nginx 终结 TLS 后反向代理到 8080，验证码、恢复码与密钥展示接口仅在 HTTPS 下使用
6. **IP 白名单**：内置 `liteark.admin-ip-whitelist-enabled=true` 已生效，拦截 `/admin/**` 与 `/api/admin/**`；也可同时在 Nginx 层限制
7. **接口文档**：默认关闭；如需 swagger-ui，设置 `LITEARK_API_DOCS=true` 或外置配置 `springdoc.*.enabled=true`
8. **内联预览**：HTML/SVG 预览响应带 `Content-Security-Policy: sandbox`（脚本不执行、无法读同源存储）与 `nosniff`；如经 Nginx 反代，请勿用 `add_header` 覆盖该头
9. **Office 预览**：双通道。装有 LibreOffice（`soffice --version` 可执行）时转 PDF 高保真预览，缓存于 `temp/office/<md5>`；未装时 docx/xlsx/pptx 自动用 Apache POI 渲染只读 HTML，缓存于 `temp/office-html/<md5>.html`（旧版 doc/xls/ppt 仍需 LibreOffice，否则提示下载）。两处缓存均由维护任务按 `recycle_retention_days` 之外的临时目录策略清理
10. **反代下载大文件**：预览/下载支持 Range，Nginx 无需额外配置；若开启 `proxy_buffering`，建议对大文件关闭以获得更好的拖动体验

## 权限配置

权限模型的默认载体是**角色**：文件夹权限按角色配置一次，该角色下的用户自动继承；个别用户需要额外权限或收窄时，再对用户单独授权（可直接指定，也可「按角色授权」引用角色默认权限）。

- 角色默认权限入口：管理后台 → **角色管理** → 目标角色「修改权限」抽屉。选择文件夹所有者 → 选择已有文件夹 → 勾选「文件查看 / 文件编辑 / 文件下载 / 文件上传」→ 保存。角色下所有用户（含后续新增）自动获得。
- 用户授权入口：管理后台 → **文件夹权限**。授权对象默认「角色」，需要单独调整时切「具体用户」；用户可选「权限来源」：直接指定 / 按角色授权（选角色模板，勾选为上限）。
- 生效范围：所选文件夹及其**全部下级**，包括此后新增的文件与文件夹；无需重复配置。
- 继承：勾选「继承上级权限」（默认）时，本级权限受上级约束，只能收窄；取消勾选则成为新的权限边界（阻断继承）。
- 按角色授权语义：用户规则记录 `source_role_id`，实际权限 = 角色在该目录的默认权限 ∩ 本次设定上限；角色默认权限调整后自动跟随，但不会超过上限。管理员角色（id=1）不能作为模板。
- 默认策略：超级管理员全部权限；资源所有者默认全权（若被显式配置规则则按规则）；其他用户未授权即不可见。
- 数据位置：`permission` 表（subject_type=user/role，subject_id，folder_id，perm_bits=view,edit,download,upload，inherit，source_role_id）。同一主体 + 同一文件夹唯一。
- 接口：`GET/POST /api/admin/permissions`、`DELETE /api/admin/permissions/{id}`、`GET /api/admin/permissions/effective`、`GET /api/admin/permissions/role-effective?roleId=&folderId=`、`GET /api/admin/folders?ownerId=`（文件夹树）。

### 用户自助授权（普通用户侧）

- 入口：网盘内进入**自己拥有的文件夹** → 工具栏「授权」（或列表行「授权」、移动端单项操作面板「授权给同事」）；已授权规则集中在「我的分享 → 文件夹授权」，可撤销或跳转到对应文件夹。
- 授权方式：直接指定权限，或「按角色授权」（读取角色默认权限，勾选为上限，面板提示实际生效权限）。
- 可授出范围：不超过自己在目标文件夹上的有效权限；只能授权自己拥有的文件夹；授权对象仅限普通用户（不含自己与管理员）。
- 接口：`GET /api/grants?folderId=`（面板数据：权限上限/候选用户与所属角色/可选角色模板及默认权限/现有规则）、`POST /api/grants`（folderId、userId、perms、inherit、可选 roleId）、`DELETE /api/grants/{id}`（仅用户规则；角色规则由管理员维护）、`GET /api/grants/mine`（我授权出去的规则，含来源角色）。
- 与后台配置共用同一张 `permission` 表与同一套递归规则；文件夹被彻底删除时，其上的规则会自动清理。
