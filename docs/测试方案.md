# 轻舟 LiteArk 系统测试方案

| 项 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-11-25 |
| 被测系统 | 轻舟 LiteArk 网盘系统（SpringBoot 2.7.18 + Java 8 + Vue3 + SQLite + 单 fat jar） |
| 被测版本 | V1.1（含内/外部分享、六权限位、并行分片上传、xlsx 多页签预览） |
| 测试环境 | http://localhost:8080（本地部署实例） |

---

## 1. 测试目标

1. 验证系统各功能模块是否满足《LiteArk需求-V1.1》《功能说明》《权限说明》《网盘功能说明》中定义的需求。
2. 验证认证、鉴权与权限计算的正确性，确保无越权、无权限放大、默认拒绝等安全约束生效。
3. 验证接口在正常、边界、异常输入下的行为符合预期，错误码语义清晰。
4. 通过真实 HTTP 调用留痕，形成可复现、可追溯的测试记录，并据此输出测试报告。

## 2. 测试范围

### 2.1 范围内的模块

| 编号 | 一级模块 | 覆盖功能点 |
|---|---|---|
| M1 | 认证与个人 | 登录、注册、当前用户、改密码、改昵称、JWT 鉴权 |
| M2 | 文件与目录 | 目录树、文件列表、搜索、面包屑、新建/重命名、复制/移动、回收站、还原、彻底删除、清空、批量下载 |
| M3 | 分片上传 | 配置探测、init 断点复用、chunk 幂等、status、complete 校验、cancel、配额与校验 |
| M4 | 预览与编辑 | 图片缩略图、内联预览、Office 双通道预览、能力探测、在线编辑、历史版本、回滚 |
| M5 | 分享 | 外部分享、内部分享（名单制）、密码/有效期/下载上限、共享浏览/下载/预览、访问记录、后台管控 |
| M6 | 授权与权限 | 六权限位、用户/角色规则、继承与阻断、角色默认权限、有效权限查询、越权授出拦截 |
| M7 | 管理后台 | 概览、用户/角色/共享管理、操作日志筛选与导出、系统配置、管理员权限校验 |
| M8 | 安全与健壮性 | 未登录拦截、越权访问、非法参数、错误码语义、响应安全头 |

### 2.2 范围外

- 浏览器 UI 交互的像素级视觉回归（本方案以接口层功能测试为主，关键点辅以页面可访问性探测）。
- 跨浏览器兼容性、移动端真机适配。
- 大规模并发压测与长时间稳定性（仅做轻量并发与幂等验证）。
- LibreOffice 转换质量的视觉比对（仅验证通道可用与返回结构）。

## 3. 测试环境

| 项 | 值 |
|---|---|
| 服务地址 | `http://localhost:8080` |
| 数据库 | SQLite `data/liteark.db` |
| 鉴权方式 | JWT，请求头 `Authorization: Bearer <token>`；下载/预览可退化为 `?token=` |
| 响应约定 | `{"code":0,"msg":"ok","data":...}`；业务失败 HTTP 200 + `code≠0`；Security 层拦截为真实 401/403 |
| 测试工具 | Python 3 + requests，HTTP 接口自动化测试脚本 |
| 默认账号 | `admin/admin123`（超级管理员）、`demo/123456`（普通用户） |

## 4. 测试策略与类型

| 测试类型 | 说明 | 覆盖重点 |
|---|---|---|
| 功能测试 | 按需求逐项验证正向流程 | M1–M7 各主流程 |
| 权限测试 | 构造不同角色/权限组合的测试用户，交叉验证可见性与操作权限 | M6、M5 内部分享名单 |
| 接口测试 | 直接调用 HTTP 接口，断言 code/msg/data | 全部模块 |
| 边界值测试 | 空值、超长、非法格式、数量上限、配额上限 | 注册、上传、分享参数 |
| 异常/安全测试 | 未登录、越权、伪造 token、访问他人资源、非法分页 | M8 |
| 幂等与一致性 | 分片重复上传、断点续传、下载计数、配额增减 | M3、M5、M2 |

## 5. 测试用户设计

为避免污染正式数据，测试用户统一以 `qa_` 前缀创建，测试结束后可整体清理。密码统一 `Test@123456`。

| 账号 | 昵称 | 角色 | 权限配置 | 用途 |
|---|---|---|---|---|
| `admin` | 超级管理员 | role 1 | 系统全权 | 管理员功能、授源、后台配置 |
| `qa_owner` | 测试-所有者 | 普通用户 role 2 | 自己目录全权 | 作为授权/分享源，创建测试文件夹与文件 |
| `qa_view` | 测试-只读 | 普通用户 role 2 | 仅 `view` | 验证只读可见、不可改不可分享 |
| `qa_edit` | 测试-编辑 | 普通用户 role 2 | `view,edit,download,upload` | 验证编辑/上传、无分享权 |
| `qa_share` | 测试-分享 | 普通用户 role 2 | `view,download,share_internal,share_external` | 验证内/外部分享发起 |
| `qa_guest` | 测试-访客 | 普通用户 role 2 | 无授权 | 默认拒绝、内部分享名单外用户 |

> 说明：普通用户角色（role 2）默认权限为空集，需由文件夹所有者通过授权规则显式授予；测试脚本会在 `qa_owner` 的专用文件夹上配置上述规则，验证权限链实时生效。

## 7. 缺陷分级

| 级别 | 定义 | 示例 |
|---|---|---|
| 阻断（Blocker） | 核心流程不可用、数据丢失、严重越权 | 未授权可下载他人文件、上传数据损坏 |
| 严重（Critical） | 主要功能失效、权限计算错误 | 授权不生效、外部分享绕过密码 |
| 一般（Major） | 次要功能异常、边界处理不当 | 分页错误、错误提示不清晰 |
| 轻微（Minor） | 体验/文案/样式问题 | 列名、居中、文案 |

## 8. 通过标准

1. 用例执行率 100%；
2. 阻断、严重级别缺陷为 0；
3. 一般及以上缺陷全部有明确结论（修复或接受）；
4. 核心流程（登录、上传、下载、分享、权限）功能测试通过率 100%。

## 9. 执行与产出

1. 使用 Python 自动化脚本创建测试用户与测试数据，逐条执行用例，输出机器可读的 `test-results.json` 与可读的《测试执行记录.md》。
2. 测试完成后清理测试用户与测试数据，恢复数据库至测试前状态。
3. 基于执行结果输出《测试报告.md》。

> 所有测试为对本地测试实例的操作，不修改产品源码；测试脚本与数据准备逻辑随文档一并留存以便复现。
